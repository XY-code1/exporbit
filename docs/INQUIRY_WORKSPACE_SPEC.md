## 1. 信息架构

```text
Inquiry Workspace
├─ 左侧：Inquiry Navigation
│  ├─ 搜索 / 状态筛选 / 最近处理
│  ├─ 询盘列表
│  └─ 新建询盘
├─ 中间：Inquiry Workspace
│  ├─ 顶部：当前询盘标题 / 客户 / 当前阶段
│  ├─ 原始询盘入口
│  ├─ Level 1：Business Snapshot（默认）
│  ├─ 客户需求、数量、目标国家
│  ├─ 产品匹配状态
│  ├─ 关键需求缺口
│  └─ 下一步建议
│  └─ Level 2：Business Intelligence（按需切换）
│  ├─ Business Context Matching
│  ├─ Customer Intelligence
│  ├─ Knowledge Intelligence
│  ├─ Recommended Actions
│  └─ Communication Studio
├─ 右侧：Action Panel
│  ├─ 下一步建议 / 待确认事项
│  ├─ 业务行动
│  └─ 商务回复入口
└─ Level 3：Research & Evidence（从中间或右侧就地展开）
   ├─ 原始询盘与定位
   ├─ 企业内部资料
   ├─ 知乎/海外原始来源
   ├─ 证据详情、时间、可信状态
   ├─ 观点冲突与待核实项
   └─ 修改/确认记录
```

桌面端采用“左侧导航 + 中间工作区 + 右侧行动面板”。右侧只显示当前最相关的行动，不与中间内容重复堆叠。Level 3 从中间或右侧触发为覆盖式证据抽屉，关闭后回到触发位置。平板将左右侧区改为抽屉；移动端单列，摘要优先，行动面板成为底部入口，证据使用全屏详情。

## 2. 全局交互规则

### 2.1 信息状态
PRD 状态映射：
- `CONFIRMED`：有明确依据；界面同时显示来源。用户确认行为单独显示“已人工确认”，不把无依据内容伪装成事实。
- `INFERRED`：AI 推断；显示依据和可能的不确定性。
- `NEEDS_CONFIRMATION`：需要用户或客户确认。
- `INSUFFICIENT_DATA`：信息不足；列出缺失项及影响。
- `UNAVAILABLE`：数据源当前不可用。

产品匹配仅使用 `MATCH / MISMATCH / UNKNOWN`；人工修正显示修正人、时间、原值、新值与原因。

### 2.2 Evidence-to-Action
每条建议必须能回溯：
`Business Question → Knowledge Discovery → Evidence → Business Insight → Recommended Action`。
没有证据时只能建议补资料、核实或询问；不得输出确定性结论。知乎条目按社区经验展示，不冒充法规或官方事实。

### 2.3 编辑、保存与联动
- 编辑不自动覆盖原值；进入“未保存修改”状态。
- 保存后成为“人工修改·待确认”；确认后记录确认人和时间。
- 上游需求变化时，仅将受影响的匹配、洞察、行动和回复标记为“待复核”，不静默重写。
- 切换询盘前若有未保存内容，提供保存并离开、放弃并离开、继续编辑。
- 外部源失败不改变询盘业务状态，也不阻塞匹配、行动和回复。

### 2.4 通用状态
所有模块复用：正常、局部加载、空、异常、数据不足、外部源不可用、用户修改、保存成功。加载不清空旧内容；错误不丢输入；成功状态在区域内持续可见，不只依赖瞬时 Toast。

## 3. 模块详细设计

### A. Inquiry Navigation
1. **功能目标：** 快速定位、切换和创建询盘，看到当前处理进度。
2. **展示内容：** 搜索框、状态筛选、最近处理、列表项（客户/主题、更新时间、状态、待复核提示）、新建按钮。
3. **用户操作：** 搜索客户名/主题/询盘编号；组合筛选；选择最近记录；打开询盘；新建。
4. **系统反馈：** 即时更新结果数；当前行高亮；切换后恢复该询盘上次区域和滚动位置；未保存内容触发离开保护。
5. **数据状态：** 使用 `NEW / ANALYZING / NEEDS_INFORMATION / READY_TO_REPLY / COMPLETED / FAILED`。最近处理默认 7 天并允许时间筛选；“待复核/未保存”作为独立标记，不与业务状态混用。
6. **加载状态：** 列表骨架；已打开的主区内容保留。
7. **空状态：** 无询盘时引导新建；筛选无结果时提供清除条件。
8. **异常状态：** 列表加载失败显示重试，不遮蔽已打开询盘。
9. **模块关系：** 创建进入 B；列表状态由 C 核对和 H 保存驱动；待复核来自 D–H 联动。
10. **验收标准：** 搜索与筛选可叠加；切换后上下文保留；未保存内容不会丢失；最近处理可回到原位置。

### B. Inquiry Import
1. **功能目标：** 用文本、PDF、图片、EML 创建可追溯原文的询盘。
2. **展示内容：** 四种入口、附件队列、解析进度、原文预览、抽取预览、失败原因、重复提示。
3. **用户操作：** 粘贴文本；添加/替换/移除文件；校正标题和内容；确认创建。
4. **系统反馈：** 附件级上传/解析进度；PDF 标页、图片标区域、EML 区分邮件头/当前正文/引用历史；创建时防重复提交。
5. **数据状态：** 原始内容与抽取内容并存；导入成功不等于字段已确认。系统可提示“疑似重复”，不自动删除或合并；合并前展示关联记录，只有用户确认后才执行。识别阈值仍待技术验证。
6. **加载状态：** 每个附件独立进度；已成功内容可预览。
7. **空状态：** 未输入内容时禁用创建，并说明可用方式。
8. **异常状态：** 不支持、损坏、加密或无法识别时显示具体文件、原因和重试/替换/移除/粘贴入口；部分成功允许明确排除失败项后继续。
9. **模块关系：** 创建后进入 C；原文作为 L3 证据；重复项可跳转现有询盘或进入合并预览。任何合并都需要用户确认并保留关联记录。
10. **验收标准：** 四种方式均保留原文；失败不静默丢弃；部分成功可控；重复提示不自动覆盖或合并记录。

### C. Business Snapshot
1. **功能目标：** 在首次分析后用最少信息帮助业务员判断“客户要什么、能否供应、缺什么、下一步做什么”。
2. **展示内容：** 客户需求、规格与数量、目标国家/市场、产品匹配概览、关键缺口、单一下一步主建议；客户/研究仅显示摘要。
3. **用户操作：** 查看原文依据；就地修改字段；确认字段；展开缺口；跳转匹配或行动。
4. **系统反馈：** 显示原值/新值、状态和影响；保存后标“人工修改·待确认”；确认后更新时间；影响项进入待复核。
5. **数据状态：** 使用全局五类状态；数量显示单位；目标市场与收货地不混写。
6. **加载状态：** 分区骨架并显示“正在解析/匹配”；原文始终可打开。
7. **空状态：** 无可解析内容时引导返回导入补充原文。
8. **异常状态：** AI 分析失败时可重试或手工录入；已录入字段保留。
9. **模块关系：** 需求驱动 D；客户线索驱动 E；缺口驱动 F/G；确认内容供 H 使用。
10. **验收标准：** 首屏完整覆盖 PRD Level 1 六类信息；不展示长证据列表；每个重要字段可追溯、修改、确认；缺数据不自动填测。

### D. Business Context Matching
1. **功能目标：** 将一个询盘的多个需求与多个企业产品逐项比较并由人工确认。
2. **展示内容：** 需求项、候选产品、产品类型/规格/MOQ/OEM-ODM/交付/认证六维矩阵、匹配依据、来源时间、未知项、主推/备选。
3. **用户操作：** 添加、删除或替换候选；展开依据；修正 `MATCH/MISMATCH/UNKNOWN`；补充产品信息；确认产品。
4. **系统反馈：** 逐项显示要求值、企业值、判断和依据；人工修改保留审计；确认时展示未解决 UNKNOWN/MISMATCH，不阻止带理由保留备选。
5. **数据状态：** 仅三种匹配状态；缺关键字段必须为 UNKNOWN；不输出虚假总匹配率。**[待确认]** 总览建议使用“5/6 已核实”而非百分比。
6. **加载状态：** 候选检索与逐项判断分别加载；手动候选入口始终可用。
7. **空状态：** 企业产品为空时提示先补资料；有产品无候选时允许手动添加或记录暂不推荐。
8. **异常状态：** 匹配失败可重试或手工建立关系；产品资料过期/来源不明显示警示，不自动判 MATCH。
9. **模块关系：** 使用 C 的需求；读取企业资料；结果供 G/H；首版可在当前询盘展示相关产品资料缺口，不自动修改产品资料；跨多次询盘的趋势统计为 P1。
10. **验收标准：** 支持询盘↔产品多对多；每维只出现三种状态；人工修正可追踪；上游变化仅影响相关判断；确认产品不等于商业承诺。

### E. Customer Intelligence
1. **功能目标：** 辅助识别客户主体、采购意图、业务匹配与风险信号，不制造风险评分。
2. **展示内容：** 企业名称、国家、官网、公开介绍/联系方式；采购产品/数量/定制/时间/市场；匹配度解释；风险信号；来源与时间。
3. **用户操作：** 修正公司名、域名、国家；选择同名主体；查看来源；修改/确认判断；标记待核实。
4. **系统反馈：** 调查进度按来源展示；主体切换显示影响；人工判断保留原依据和修改记录。
5. **数据状态：** 事实、推断、待确认、数据不足、不可用；“无结果”不等于“无风险”。
6. **加载状态：** 背景、意图、风险可独立完成；先返回部分结果。
7. **空状态：** 线索不足时列出所需信息，如公司全称、域名或国家。
8. **异常状态：** 同名主体并列等待选择；来源矛盾时并列；调查服务不可用时仍允许继续。
9. **模块关系：** 读取 B/C 线索；证据进入 F；洞察进入 G；仅用户选定且适合外发的信息进入 H。
10. **验收标准：** 主体未确认前不自动归因；风险都有依据；信息不足不生成评分；来源失败不阻塞核心流程。

### F. Knowledge Intelligence
1. **功能目标：** 围绕业务问题检索知乎、海外公开信息和企业证据，并转化为可用洞察。
2. **展示内容：** 业务问题列表、自动推荐主题、手动搜索、分来源结果、证据卡、来源/作者/时间/获取时间、人工冲突对照、关联关系。自动观点冲突识别为 P1。
3. **用户操作：** 修改/删除推荐主题；添加问题；执行搜索；选择/排除证据；关联业务问题；记录洞察；标记冲突。
4. **系统反馈：** 各来源独立进度和结果数；证据关联后显示链路；取消关联时受影响洞察/行动待复核。
5. **数据状态：** 知乎社区、海外公开、企业证据分组；可信状态与信息性质分别展示；历史证据保留获取时间。
6. **加载状态：** 来源级加载，不锁整页；已保存证据可继续使用。
7. **空状态：** 无自动问题时允许手动添加；无结果时建议改写问题或补资料，不等同服务失败。
8. **异常状态：** 知乎或其他源不可用时明确来源和重试；不得伪造；仍可用其他来源完成行动和回复。
9. **模块关系：** 问题来自 C/D/E；证据支撑 G；H 仅使用用户确认的洞察/行动。知乎是可插拔来源。
10. **验收标准：** 每条采用证据可追溯；可从问题走到行动；来源冲突保留原貌；关闭知乎仍可完成闭环。

### G. Recommended Actions
1. **功能目标：** 把已知事实、洞察和缺口转成可执行且可确认的业务下一步。
2. **展示内容：** 建议内容、原因、业务问题、关联询盘/证据、信息状态、行动对象、待确认事项；按“先确认/可并行/后续”分组。
3. **用户操作：** 查看链路；编辑建议；确认/不采用/恢复；指定“向客户询问、内部核实、暂缓”；选择是否用于回复。
4. **系统反馈：** 保存修改与确认记录；无证据时提示仅能作为核实建议；不采用不删除历史。
5. **数据状态：** 待确认、已确认、不采用、待复核；“已确认”不表示已执行。
6. **加载状态：** 基于已有信息逐条生成；已有人工行动保持可用。
7. **空状态：** 没有可建议内容时引导完成需求核对或手工添加行动。
8. **异常状态：** 建议生成失败时保留手工添加；证据不可用时标记待复核，不删除建议。
9. **模块关系：** 接收 C–F；用户选择的客户向行动进入 H；内部风险和内部笔记默认不外发。
10. **验收标准：** 每项可回溯问题与证据或明确资料缺口；可人工修改确认；内部事项不会误入回复。

### H. Communication Studio
1. **功能目标：** 基于用户确认内容生成、编辑、保存和恢复多语言商务回复，守住商业承诺边界。
2. **展示内容：** 回复目标；中文/英文；Formal Business、Friendly Professional、Concise Direct 三种语气；已选要点/问题、正文编辑器、未确认信息提醒、保存状态、历史版本、版本比较。
3. **用户操作：** 选择目标/语言/语气；选入行动；生成/重新生成；编辑；保存；查看比较；恢复；最终确认。
4. **系统反馈：** 生成候选不覆盖手工正文；保存显示版本号/作者/时间；恢复先进入编辑区并标未保存，再保存为新版本。
5. **数据状态：** 草稿未保存、保存中、已保存、含待补内容、最终确认。比赛版由当前用户确认；可撤销最终确认，但保留历史版本和操作记录。
6. **加载状态：** 保留当前正文，局部显示生成中；允许取消或继续编辑 **[待确认：生成期间并发编辑的冲突策略]**。
7. **空状态：** 无历史时提示首次保存后产生版本；用户可跳过 AI 直接编写。
8. **异常状态：** 生成失败保留输入并可重试；保存失败保留正文且不产生假版本；未替换占位或未确认承诺需提示。
9. **模块关系：** 使用已确认需求、匹配、客户信息和已选行动；保存后回写 A；不自动发送邮件。
10. **验收标准：** 多语言草稿独立；重新生成不覆盖人工内容；历史比较/恢复完整；未知价格、交期、认证、能力、付款条件不得写成确定承诺。

## 4. 响应式与可访问性
- 桌面优先；1024px 下导航抽屉化，390px 下矩阵改为按需求项分组的候选卡。
- 主要触控目标至少 44px；状态不只用颜色；数字与单位不可分离。
- 键盘可完成搜索、候选选择、确认、保存和抽屉开关；焦点关闭后回触发控件。
- 错误与控件通过可读标签关联；异步状态向辅助技术播报，但不抢占用户焦点。

## 5. 进入视觉设计的输入与出口

### 已具备
- 页面区域、三级层次、八模块职责、核心操作和完整状态已定义。
- 三个核心机制已落入操作与验收规则。
- MVP 边界明确，不含发送、自动承诺、技术实现。

### 仍需产品确认
见 0.3 的四项剩余差距。文件限制等待技术验证，低保真不显示未经验证的上限。

### 结论
可进入低保真 UI 设计。进入高保真前，应优先确认上传限制、重复识别/合并细则、客户信息刷新与隐私文案，以及生成期间编辑冲突策略。
