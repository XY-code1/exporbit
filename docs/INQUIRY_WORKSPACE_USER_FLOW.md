# Exporbit Inquiry Workspace 核心用户流程

> 状态：评审稿｜2026-11-14  
> 依据：PRD V1.1 与 `INQUIRY_WORKSPACE_SPEC.md`。本文只定义产品交互，不定义接口或实现。

## 1. 主流程总览

```text
进入工作台
→ 新建询盘
→ 选择文本 / PDF / 图片 / EML
→ 预览原文、处理失败项与可能重复
→ 创建询盘（待核对）
→ 查看 Level 1 Business Snapshot
→ 修改并确认需求
→ 查看多产品候选
→ 逐项核查 MATCH / MISMATCH / UNKNOWN
→ 人工确认主推与备选
→ 按需调查客户与研究知识
→ Business Question → Evidence → Insight → Action
→ 确认或修改行动
→ 选择回复目标、语言、语气和内容
→ 生成/编辑回复
→ 保存版本并最终确认
→ 返回列表（回复已保存）
```

Level 2 与 Level 3 是按需深入，不强迫所有用户按固定顺序阅读。只有生成内容所依赖的结论需要先由用户确认。

## 2. 流程 F1：导入与建档

1. 用户点击“新建询盘”。
2. 系统打开导入面板，不离开列表上下文。
3. 用户粘贴文本或添加多个文件。
4. 系统逐附件解析并保留原文；成功内容立即可预览，失败内容就地说明原因。
5. 系统检查可能重复项：只提示，不自动删除或合并；合并前展示关联记录。
6. 用户可以：
   - 打开现有询盘；
   - 继续创建新询盘；
   - 查看关联记录并由用户确认合并；
   - 移除失败项后继续；
   - 替换/重试失败文件。
7. 用户确认创建。
8. 系统防重复提交，创建一条 `NEW` 记录，打开 Business Snapshot。

**失败分支：** 没有任何可用内容时不可创建；已有成功内容不会被失败重试清空。

## 3. 流程 F2：需求核对

1. 系统展示 Level 1：需求、规格/数量、目标市场、匹配、缺口、下一步。
2. 用户点击字段查看原文定位和信息状态。
3. 用户对错误或缺失字段进行修改。
4. 系统显示原值、新值和影响范围；用户保存后进入“人工修改·待确认”。
5. 用户逐项确认，或在保留明确缺口的前提下完成核对。
6. 系统进入 `ANALYZING`；若缺少阻断性信息则进入 `NEEDS_INFORMATION`，否则继续更新产品候选。

**数据不足分支：** 数量、目标市场等未知时继续流程，但相关 MOQ、认证或交付判断必须为 UNKNOWN；回复使用询问措辞。

## 4. 流程 F3：多产品匹配

1. 系统按需求项推荐多个候选。
2. 用户比较六维状态与依据。
3. 用户可删除候选、手动添加、修正状态或补产品资料。
4. 每次修正记录原值、新值、原因、用户和时间。
5. 用户选择主推与备选并确认；MISMATCH 可保留为备选但需理由，UNKNOWN 明确待核实。
6. 确认结果供行动与回复使用。

**空分支：** 产品库为空时引导补资料；无推荐时允许手动选产品或记录“暂不推荐”，并进入澄清回复。

## 5. 流程 F4：客户调查

1. 系统从询盘提取公司名、域名、国家。
2. 用户核对搜索主体。
3. 系统并行返回企业背景、采购意图、业务匹配、风险信号。
4. 同名主体并列等待选择；未选择前不归因。
5. 用户查看来源、修改/确认判断或标记待核实。
6. 确认的洞察进入行动候选。

**失败分支：** 无资料显示“尚未核实”，不显示“低风险”；外部服务不可用不阻断匹配和回复。

## 6. 流程 F5：知识与证据到行动

1. 系统从需求缺口、匹配 UNKNOWN 和客户调查生成业务问题。
2. 用户编辑、删除或新增问题。
3. 用户启动知乎、海外公开信息或企业资料检索。
4. 各来源独立返回结果；用户查看原文、来源类型、时间和适用对象。
5. 用户选择证据并关联业务问题。
6. 系统/用户形成 Business Insight；若来源冲突，则并列展示并标待核实。
7. 系统给出 Recommended Action。
8. 用户编辑、确认、不采用或指定内部/客户向处理方式。

**知乎降级：** 知乎关闭、无结果或不可用时，保留历史证据，并继续使用海外与企业证据。没有证据时只生成核实或补资料行动。

## 7. 流程 F6：回复生成、保存与恢复

1. 用户进入 Communication Studio。
2. 用户选择回复目标、语言、语气以及要纳入的行动和问题。
3. 系统检查未确认的价格、交期、认证、能力与付款条件。
4. 系统生成候选；缺失内容采用询问或保留表达。
5. 用户编辑。重新生成只产生候选，不覆盖人工正文。
6. 用户保存；系统校验空白、占位和未确认承诺。
7. 保存成功生成新版本，显示版本号、语言、作者和时间；具备可回复内容时为 `READY_TO_REPLY`，用户最终确认后为 `COMPLETED`。
8. 用户打开历史版本，预览或比较。
9. 用户选择恢复：
   - 如当前有未保存内容，先选择保存、放弃或取消；
   - 所选版本复制到编辑区并标“未保存”；
   - 再次保存产生新版本，旧版本不变。
10. 当前用户可最终确认，也可撤销；撤销及再次确认均保留历史版本和操作记录。系统不发送邮件。

### 7.1 询盘状态迁移

- `NEW`：导入创建成功，尚未开始分析。
- `ANALYZING`：正在解析、匹配或生成业务分析。
- `NEEDS_INFORMATION`：分析完成但缺少阻断下一步的关键资料；补充后回到 `ANALYZING`。
- `READY_TO_REPLY`：需求与关键行动已具备生成/确认回复的条件。
- `COMPLETED`：当前用户完成最终确认；撤销最终确认后回到 `READY_TO_REPLY`。
- `FAILED`：核心处理失败且无法形成可用结果；重试后进入 `ANALYZING`，手工补录也可继续流程。

外部来源单点失败不触发 `FAILED`；未保存、待复核是独立编辑标记。

## 8. 流程 F7：上游变化后的复核

1. 用户修改数量、市场或规格。
2. 系统计算关联范围，只将相关匹配、洞察、行动和当前草稿标“待复核”。
3. 用户查看差异，选择采纳更新或保留人工值并填写原因。
4. 用户重新确认相关行动。
5. 已保存回复历史不变；当前编辑区提示相关依据已变化。
6. 用户按需生成/编辑并保存新版本。

## 9. 跨流程状态约束

- 加载、失败或来源不可用不得清空用户输入。
- 保存失败不得推进业务状态。
- “已确认”不等于已执行；“回复已保存”不等于已发送。
- 历史证据不因来源停用而删除，需显示取得时间和当前可访问状态。
- 所有关键结论可从行动回溯至证据，从证据回溯至业务问题与原始来源。
