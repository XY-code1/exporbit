# Exporbit 产品决策记录 V1.0

> 状态：UI 设计工作依据  
> 日期：2026-11-14  
> 来源：用户提交的《Product Decisions & UI Design Handoff V1.0》  
> 说明：本文件区分“已确认方向”“建议性决策”和“技术验证待确定”，不改写 PRD V1.1。

## 1. 决策层级

- **已确认方向：** 产品定位、五项功能决策、三个核心机制和统一可信度规则，不得在 UI 设计中擅自改变。
- **建议性决策：** 本次交接第 5 章给出的具体状态、时间和选项，用作低保真 UI 基线；在 PRD 正式并入项目或产品负责人冻结前，保留“建议性决策”标签。
- **技术验证待确定：** 需要通过模型、解析能力或工程验证才能决定的限制，不得虚构数值。

## 2. 已确认方向

1. 首期服务中国中小型智能硬件和消费电子出口企业的一线业务员。
2. 以海外询盘为入口，产品形态为 AI 商务工作台，不是邮件生成器或传统 CRM。
3. 导入支持文本、PDF、图片、EML；后续再做邮箱集成。
4. 企业产品资料支持手工录入、文件上传和持续维护。
5. 客户调查覆盖企业背景、采购意图、业务匹配度和风险信号。
6. 知乎采用自动推荐主题 + 用户手动搜索，是可插拔来源，不是核心流程依赖。
7. 回复支持 AI 生成、人工编辑、保存和历史版本；MVP 不自动发送。
8. 采用 Progressive Intelligence、Evidence-to-Action、Business Context Matching。
9. 重要信息使用 `CONFIRMED / INFERRED / NEEDS_CONFIRMATION / INSUFFICIENT_DATA / UNAVAILABLE`；匹配使用 `MATCH / MISMATCH / UNKNOWN`。
10. 人工修改保留；缺少证据不生成精确风险分数；AI 不承诺未确认价格、交期、认证或能力。

## 3. 建议性决策（本阶段 UI 基线）

### D-01 询盘状态

| 状态 | 展示 | 进入条件 | 离开条件 |
|---|---|---|---|
| `NEW` | 待处理 | 导入创建成功 | 用户开始分析 |
| `ANALYZING` | 分析中 | 开始/重试解析与匹配 | 完成分析或核心失败 |
| `NEEDS_INFORMATION` | 待补充信息 | 存在阻断下一步的关键缺口 | 用户补充后重回分析 |
| `READY_TO_REPLY` | 待回复 | 已具备可确认回复的需求与行动 | 最终确认或上游变化 |
| `COMPLETED` | 已完成 | 当前用户完成最终确认 | 撤销确认后回到待回复 |
| `FAILED` | 处理失败 | 核心处理失败且无可用结果 | 重试或手工补录后分析 |

外部单一来源不可用不进入 `FAILED`。未保存、待复核属于编辑标记，不是询盘状态。

### D-02 最近处理
默认展示最近 7 天的活动；允许按时间筛选。

### D-03 重复询盘
允许提示疑似重复；不自动删除或合并。合并前展示关联记录，只有用户确认后执行。

### D-04 回复语言与语气
- 语言：中文、英文；其他语言以后根据模型能力扩展。
- 语气：Formal Business、Friendly Professional、Concise Direct。
- 用户始终可以编辑最终内容。

### D-05 最终确认
单用户比赛版由当前用户确认。允许撤销，但保留历史版本、确认和撤销记录。

### D-06 客户调查来源
企业官网、企业公开资料、海外公开网页、知乎社区内容。必须显示来源类别；社区观点不得当作企业事实。

### D-07 观点冲突
自动识别为 P1。P0 只保证不同来源观点可见，并支持人工对照和标记。

### D-08 产品资料补全
P0 在当前询盘内显示相关产品资料缺口，不自动修改产品资料。跨多次历史询盘的趋势统计为 P1。

## 4. 技术验证待确定

1. 单文件大小、页数、格式细分和单次上传数量。
2. 疑似重复算法阈值、字段权重及合并字段冲突规则。
3. 客户调查刷新周期和隐私提示文案。
4. 回复版本命名格式与生成期间并发编辑策略。

低保真 UI 只表达格式说明、进度、失败和重试，不展示未经验证的上限。

## 5. MVP 边界

- 不自动发送邮件、报价、承诺、签约或交易。
- 不做复杂团队审批、完整 CRM 或跨询盘趋势看板。
- 不把自动观点冲突识别做成 P0。
- 不自动修改企业产品档案。
- 不引入数据库、API 或技术架构设计。
