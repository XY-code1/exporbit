# Exporbit Inquiry Workspace 验收标准

> 状态：评审稿｜2026-11-14  
> 用途：产品评审与后续 UI/研发验收输入；不包含技术方案。

## 1. 总体验收

- **G-01** 默认首屏只展示 Level 1 的需求、规格/数量、目标市场、匹配状态、关键缺口和下一步，不出现长搜索结果。
- **G-02** 用户可从 Level 1 到 Level 2，再打开 Level 3 原文/证据；关闭后返回原触发位置。
- **G-03** 重要信息能区分 `CONFIRMED / INFERRED / NEEDS_CONFIRMATION / INSUFFICIENT_DATA / UNAVAILABLE`。
- **G-04** 产品匹配项只使用 `MATCH / MISMATCH / UNKNOWN`；缺关键字段必须为 UNKNOWN。
- **G-05** 每项重要建议可追溯业务问题、证据或明确的资料缺口；无证据不输出确定性业务结论。
- **G-06** 人工修改保留原值、新值、修改者、时间与原因；上游变化不静默覆盖人工内容。
- **G-07** 知乎或全部外部来源不可用时，用户仍可完成需求核对、产品匹配/记录缺口、确认行动、编辑并保存回复。
- **G-08** 系统不自动发送邮件，不自动承诺未确认价格、交期、认证、产品能力和付款条件。

## 2. 模块 A：Inquiry Navigation

- **A-01** 搜索客户名、主题和询盘编号均能得到结果，搜索与状态筛选可叠加。
- **A-02** 最近处理记录可打开对应询盘，并恢复上次区域。
- **A-03** 筛选无结果时提供清除条件；无询盘时提供新建入口。
- **A-04** 有未保存内容时切换询盘，用户可保存并离开、放弃并离开或继续编辑；继续编辑不丢内容。
- **A-05** 列表失败时已打开询盘保持可用。
- **A-06** 状态只使用 `NEW / ANALYZING / NEEDS_INFORMATION / READY_TO_REPLY / COMPLETED / FAILED`；每次迁移符合文档条件；最近处理默认 7 天并支持时间筛选。

## 3. 模块 B：Inquiry Import

- **B-01** 文本、PDF、图片和 EML 可分别创建询盘，并保留原始内容。
- **B-02** EML 当前正文、邮件头和引用历史可区分；引用历史不默认当作当前要求。
- **B-03** 有效与损坏文件混合时，成功项可预览；用户明确排除失败项后可继续。
- **B-04** 不支持、加密或解析失败显示文件级原因和可执行下一步，不静默丢弃。
- **B-05** 没有可用内容时不能创建。
- **B-06** 可能重复项只提示，不自动删除或合并；合并前展示关联记录，并且只有用户确认后才执行。

## 4. 模块 C：Business Snapshot

- **C-01** 首屏覆盖 PRD Level 1 六类必需信息。
- **C-02** 每个重要字段可查看原文或来源；无值显示“未提供/信息不足”，不填 0 或推测值。
- **C-03** 修改字段显示差异与影响；保存和确认是可区分动作。
- **C-04** AI 分析失败时允许重试或手工录入，已录入内容保留。
- **C-05** 保留缺口仍可继续后续流程，但受影响判断为 UNKNOWN 或待确认。

## 5. 模块 D：Business Context Matching

- **D-01** 同一询盘可关联多个产品，同一产品可在不同询盘或同一询盘多个需求项中复用。
- **D-02** 产品类型、规格、MOQ、OEM/ODM、交付、认证可逐项查看要求值、企业值、状态、依据和资料时间。
- **D-03** 用户可添加、删除、替换候选，修改匹配状态并确认主推/备选。
- **D-04** 缺数据、资料过期或来源不明时不会判为 MATCH。
- **D-05** MISMATCH 可带理由保留为备选；UNKNOWN 明确待核实；不输出虚假高匹配率。
- **D-06** 修改数量仅使相关 MOQ/交付判断待复核，无关确认保持不变。
- **D-07** 产品库为空或无候选时仍可手工选择或记录暂不推荐。

## 6. 模块 E：Customer Intelligence

- **E-01** 企业背景、采购意图、业务匹配和风险信号分区展示并带来源。
- **E-02** 同名主体未选择前不自动归因。
- **E-03** 无结果显示尚未核实，不显示低风险，也不生成风险评分。
- **E-04** 每个风险信号可查看实际依据；“风险信号”不表述为欺诈认定。
- **E-05** 调查服务失败不阻断其他模块。

## 7. 模块 F：Knowledge Intelligence

- **F-01** 用户可使用、修改、删除自动问题并手工新增业务问题。
- **F-02** 知乎、海外公开与企业证据明确分组；社区经验不显示为官方法规。
- **F-03** 采用的证据包含可获取的标题、来源、类别、链接/文件引用、作者、发布时间、获取时间、摘要和关联问题；不可获取项明确为空，不编造。
- **F-04** 用户可把证据关联/取消关联业务问题；取消后受影响洞察与行动待复核。
- **F-05** 冲突证据并列展示来源、时间和适用条件，允许保留待核实，不强制合并。
- **F-05a** 首版只要求人工对照不同来源观点，不把自动观点冲突识别当作 P0 完成条件。
- **F-06** “无结果”与“来源不可用”表现不同。
- **F-07** 知乎停用后历史证据保留，并标示取得时间与当前不可重新验证状态。

## 8. 模块 G：Recommended Actions

- **R-01** 行动显示内容、原因、业务问题、证据/资料缺口、信息状态和用户需执行的步骤。
- **R-02** 用户可编辑、确认、不采用和恢复；不采用不会删除历史。
- **R-03** 行动可标为向客户询问、内部核实或暂缓。
- **R-04** 内部风险和内部笔记默认不进入外发回复。
- **R-05** “已确认”不显示为“已执行”。

## 9. 模块 H：Communication Studio

- **H-01** 用户可选择回复目标、语言、语气和纳入内容。
- **H-01a** 比赛版至少提供中文、英文，以及 Formal Business、Friendly Professional、Concise Direct 三种语气。
- **H-02** 用户可跳过生成直接编辑；生成失败不影响手工编辑。
- **H-03** 多语言草稿和版本独立，重新生成不覆盖人工正文或其他语言内容。
- **H-04** 未确认价格、交期、认证、能力和付款条件不会被写成确定承诺；缺口使用询问/保留表达。
- **H-05** 保存失败保留正文且不产生成功版本；重试成功只新增一个版本。
- **H-06** 历史版本可查看、比较和恢复；恢复到编辑区后再保存形成新版本，旧版本不变。
- **H-07** 没有历史时显示首次保存提示；已保存显示版本号、语言、作者和时间。
- **H-08** 最终确认不触发邮件发送。
- **H-09** 当前用户可撤销最终确认；撤销和再次确认保留全部版本与操作记录。

## 10. 状态与恢复验收

- **S-01 正常：** 显示内容、状态、来源及一个明确主操作。
- **S-02 加载：** 局部占位；旧内容和用户输入保留；非依赖区域仍可操作。
- **S-03 空：** 无询盘、无筛选结果、无证据、无历史分别提供对应下一步。
- **S-04 错误：** 显示失败对象、原因与重试/替代动作；不清空输入。
- **S-05 数据不足：** 明确缺失项和影响；不伪造结果。
- **S-06 外部源不可用：** 局部降级，保留历史证据和核心路径。
- **S-07 用户修改：** 原值/新值、未保存/待确认状态可见；离开前保护。
- **S-08 保存成功：** 区域内持续显示保存时间或版本；不只依赖瞬时提示。

## 11. 响应式与可访问性验收

- **X-01** 在 1440px、1024px、390px 完成主流程，无全页横向溢出或被遮挡的主操作。
- **X-02** 移动端矩阵转换为候选卡后，六维状态、依据、人工修正与产品确认仍可完成。
- **X-03** 键盘可完成搜索、筛选、选候选、确认、保存和证据抽屉往返。
- **X-04** 状态不只靠颜色；错误与控件标签对辅助技术可关联；抽屉关闭后焦点返回触发点。
- **X-05** 主要移动触控目标不小于 44px。

## 12. 进入视觉设计的验收门槛

低保真视觉设计已具备决策基础。进入高保真前仍需对以下事项建立决策记录：
1. 上传大小、页数、格式和数量的技术验证结果；
2. 疑似重复识别阈值与合并字段冲突细则；
3. 客户调查刷新周期和隐私提示文案；
4. 回复版本命名及生成期间并发编辑策略。

未经验证的文件限制不得出现在 UI 文案中。
