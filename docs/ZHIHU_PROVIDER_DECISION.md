# 知乎 Provider Go/No-Go 决策（阶段 0）

- 日期：2026-11-18
- 状态：**NO-GO（LIVE）**
- 影响范围：知乎实时搜索与内容获取；不影响询盘、解析、抽取、证据链路和手工导入
- 决策层级：阶段 0 技术闸门决策，后续可被新的授权证据推翻

## 1. 决策

在阶段 0 结束时不建立知乎 LIVE Provider：

- `zhihu_live` 保持 `PLANNED` 且禁用，不暴露为可执行 Provider。
- 继续使用 `zhihu_demo`（`DEMO`）和 `manual_import`（`MANUAL`）。
- DEMO 内容必须带机器字段 `is_demo=true` 与 UI 标识，不得描述为实时搜索。
- 手工导入是正式可用路径，按来源、操作者、时间和快照保存。

## 2. 依据

1. **没有已确认的授权渠道。** 当前未取得知乎官方 API、书面授权或可核验的合作条款；不能把“可能存在”当作可实施前提。
2. **公开、稳定、可维护的获取方式未验证。** 条款、限流、字段稳定性、引用与快照保留边界均无运行证据。
3. **产品原则允许 no-go。** `docs/PROVIDER_DESIGN.md` 明确知乎是当前只有 DEMO 的可插拔来源，禁止依赖未记录接口或规避访问控制；`docs/POC_VALIDATION_PLAN.md` 允许知乎 no-go，但要求核心流程在关闭后完整可用。
4. **核心链路不依赖知乎。** POC-05 已验证：DEMO 与手工证据可进入洞察链路；Provider 离线时返回 `UNAVAILABLE`，历史证据与快照仍可解释。

## 3. 后果

- 阶段 1–2 不安排知乎 LIVE 开发工作，不为其引入爬虫、代理或浏览器自动化依赖。
- 阶段 3（Knowledge & Evidence）按“DEMO + 手工导入”设计研究入口与 Evidence Drawer。
- 研究能力仍可由客户原文、企业资料、手工证据及后续验证过的海外/官方来源支撑。
- 任何真实知乎内容进入产品前，必须先有授权与引用/快照保留方案。

## 4. 重新评估条件

满足以下全部条件后，另立决策记录再评估 LIVE：

1. 取得书面授权、官方 API 或明确的合作渠道，并确认允许的用途与再分发范围。
2. 有可重复的成功率、限流、字段与失败模式记录（POC 报告形式）。
3. 法律/合规确认引用、快照存储、删除与保留期限。
4. 能保持单源失败隔离：知乎不可用时核心流程与历史证据不受影响。

## 5. 禁止事项

- 不调用未文档化接口，不绕过登录、验证码、robots 或访问控制。
- 不把抓取内容或未授权内容写入测试仓库、报告或演示数据。
- 不以 DEMO 数据冒充实时结果，不在 UI 中使用“已接入知乎”等表述。
- 不为知乎单独引入微服务、队列或计划外基础设施。
