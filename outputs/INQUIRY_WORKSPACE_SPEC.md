# TradePilot — Inquiry Workspace 交互设计规格

**交付状态：评审稿 · 2026-11-14**  
**设计依据：** 当前任务列出的 PRD V1.1 机制与范围。工作区未附 PRD V1.1 正文，未逐条核对原文。下文的状态名、默认值、断点及保存规则为交互设计提案，不视为已确认的 PRD 条款。  
**范围：** 从导入到保存商务回复版本。不涉及自动发信、报价审批、技术架构或实现。文件大小、支持的具体图片格式、语言清单及企业角色权限待对照 PRD 确定；界面在输入前展示实际限制。

## 1. 页面信息架构图

```text
Inquiry Workspace
├─ 左栏 · Inquiry Navigation
│  ├─ 新建询盘 → Inquiry Import → 导入预览 → 创建并选中询盘
│  └─ 搜索 / 状态筛选 / 询盘列表
├─ 主区 · 当前询盘
│  ├─ 粘性页头：标题 / 客户 / 进度 / 当前主操作
│  ├─ L1 Business Snapshot：需求 / 匹配 / 关键缺口 / 下一步
│  └─ L2 区域导航（保留当前询盘）
│     ├─ 产品匹配 Business Context Matching
│     ├─ 客户调查 Customer Intelligence
│     ├─ 知识研究 Knowledge Intelligence
│     ├─ 业务建议 Recommended Actions
│     └─ 回复 Communication Studio
└─ L3 就地详情：原文定位 / 证据与冲突 / 匹配依据 / 历史版本
   关闭后回到原区域、原位置及触发控件

主路径：导入 → 核对需求 → 比较并确认产品 → 确认行动 → 编辑并保存回复
辅助路径：客户调查 / 知识研究 → 业务问题 → 行动 → 回复
降级路径：外部资料不可用 → 原询盘 + 企业资料 → 澄清建议 → 保存回复
```

**布局：** 桌面 ≥1200px 显示左栏与主区；L3 默认收起，展开时用侧边抽屉，空间足够时不遮挡当前工作内容。不足 1200px 时列表切换为抽屉；≤767px 单列，先摘要后区域切换，L3 使用全屏详情。横向匹配比较在窄屏变成按需求项分组的候选卡，保留筛选和已选产品。主操作始终最多一个：依阶段显示「核对需求」「继续匹配」「起草回复」或「保存版本」。滚动时折叠摘要，不遮挡编辑器和错误提示。

### 1.1 三级信息展示（Progressive Intelligence）

- **L1 / 决策摘要：** 显示需求、数量、国家、匹配进度、最重要缺口与一个下一步。其余缺口折叠为「查看全部 N 项」。不展示完整搜索结果或推理长文。
- **L2 / 工作层：** 展示可比较的数据、建议理由和编辑控件。由摘要字段、区域导航或跨区链接直达对应条目；切换区域不丢弃当前输入。
- **L3 / 核查层：** 显示原文上下文、来源位置与日期、证据冲突、人工修改与确认记录。证据打开不带离当前询盘；外部原文链接为可选，不是完成操作的前提。

## 2. 共用决策规则

**事实、推断、待确认分别标注。** 「事实」必须指向原始依据，且准确表述其证明范围，例如「客户邮件写明 1,000 台」不是「客户已承诺下单」；「推断」显示依据与可能的替代解释；「待确认」说明缺什么及向谁核实。无数据用「未提供」，不填 0 或默认值。来源可信状态单独标注「已核验 / 未核验 / 存在冲突」，不得以来源知名度代替核验。人工确认是业务处置状态，不会将无依据推断自动升级为事实。

**Evidence-to-Action。** 行动卡显示「业务问题 → 相关证据 → 建议行动」，例如「德国版认证是否覆盖候选型号？」→「邮件要求 CE；企业资料仅覆盖另一型号」→「向产品团队核实证书覆盖范围」。问题和证据均可展开；无证据时只可建议核实、补资料或询问，并展示缺口。多条证据冲突时并列呈现来源、日期、适用对象与分歧，允许选择采纳依据并填写理由，或保留待核实。风险信号不等于客户结论。

**人工确认及重算。** 需求、匹配结论、客户判断和行动可逐项修改、保存与确认。编辑态显示原值、新值与依据；关键判断覆盖需填写原因。保存未确认的修改显示「人工修改 · 待确认」；确认后记录确认人、时间与依据。上游字段变化只把受影响的确认标为「待复核」，保留旧值与历史，不静默覆盖人工编辑；重新分析提供差异与采纳/保留入口。当前回复标注相关变化，不自动改写已编辑或历史版本。

**列表进度。** 「待核对」→「处理中」→「回复已保存」。确认需求核对结果后进入处理中，即使还有明确标记的缺口；首次成功保存回复后进入回复已保存。已保存后新增未保存编辑或出现相关上游变化，用独立标记「有未保存改动」「待复核」，仍可查看最近已保存版本。外部来源失败或 AI 加载不改变业务进度。回复已保存不是已发送。

## 3. 页面区域与操作契约

下列操作均按 **用户输入 → 系统反馈 → 后续状态** 描述。

### 3.1 Inquiry Navigation
- 列表项显示客户/主题、更新时间、业务状态和待复核提示，当前行高亮；默认最近更新优先。输入客户名、主题或询盘编号并选择状态 → 更新结果及计数 → 保留当前询盘与筛选上下文；找不到结果可清空筛选，不提示删除或新建替代。
- 选择询盘 → 主区切换并显示该询盘进度 → 返回列表保留筛选和滚动。若有未保存修改，提供「保存并离开 / 放弃并离开 / 继续编辑」；保存失败留在原询盘。
- 点击「新建询盘」→ 打开导入面板 → 创建成功后打开新询盘；若新记录不符合当前筛选，提示可清除筛选定位，不重置原筛选。

### 3.2 Inquiry Import
- 粘贴文本或上传 PDF、图片、EML → 展示输入预览和附件级进度；PDF 标页、图片标区域、EML 分开邮件头、当前正文与引用历史 → 进入导入预览。原始内容保留，抽取字段可校正；不得把引用历史当成当前要求。
- 修订标题、正文或抽取内容并「创建询盘」→ 显示提交状态、防重复提交 → 创建一条记录并落到「待核对」。导入不等于确认字段。
- 不支持的格式、损坏、加密或无法识别 → 文件旁显示具体原因与重试、替换、移除或粘贴文本入口。部分成功允许只用成功内容继续，确认前明确列出排除项；没有可用内容时阻止创建。重试不清空已成功附件或粘贴内容。

### 3.3 Business Snapshot
- 默认显示客户需求摘要、关键规格、采购数量及单位、目标国家、候选/已确认产品、优先缺口与下一步；区分目标市场和收货地。点击字段 → L3 定位原文；点缺口 → 跳到对应待确认事项。
- 编辑规格、数量或国家 → 就地显示差异、来源和影响提示 → 保存更新或取消；可逐项确认，也可选择「完成核对」，保留未解决缺口。缺关键参数时仍可继续匹配和起草澄清回复。

### 3.4 Business Context Matching
- 按需求项（可含不同产品线、变体或备选方案）选择企业目录候选 → 按候选逐项比较规格、MOQ、OEM/ODM、交期、认证 → 每格标记「满足 / 部分满足 / 不满足 / 待核实」，并可打开实际值、要求值、判断理由和来源。认证按目标市场及型号核查；MOQ 按订单条件，交期按批量和定制条件核查，缺条件不做肯定判断。
- 添加、替换、排除候选或修改比较结论 → 显示变更及影响 → 按“需求项 × 产品”保存和确认，可确认主推与多个备选；同一产品亦可关联多个需求项，不强制唯一 SKU。硬性不满足项仍允许保留作备选，但需理由，不显示为完全匹配。
- 无目录提示添加/补企业资料；有目录但无匹配提示手动选候选或记录「暂不推荐」，并引导起草澄清回复。没有确认的候选不可写成已推荐型号。

### 3.5 Customer Intelligence
- 选用或修订公司名、域名、国家 → 显示调查进度 → 展示企业背景、采购意图、业务匹配度、风险信号。每条显示信息性质、来源及可信状态；公司登记与邮件陈述不与采购意图混写。
- 同名主体 → 并列展示识别线索 → 人工选择、补资料或保留「主体未确认」，未确认前不把结果绑定为客户事实。修订判断可保留原证据或添加依据，记录差异。无结果不显示「无风险」，显示「尚未核实」。

### 3.6 Knowledge Intelligence
- 以当前业务问题查看自动推荐（启用时可含知乎）或输入查询词手动搜索 → 按来源分别反馈进度与结果 → 海外公开资料、知乎及人工补充资料分别展示。可按问题/来源筛选，搜索结果不自动写入业务结论。
- 展开证据 → 查看原文摘录、出处、日期、访问状态、适用市场/型号及相关性 → 选择「关联到业务问题」，再选已有行动或新建建议。取消关联保留证据，但提示受影响行动待复核。
- 对冲突证据 → 比较分歧及适用条件 → 采纳、标记冲突待核实或不采用，并保存理由。知乎关闭、无结果或不可用均不阻塞其他来源、行动或回复；历史条目保留上次取得时间及不可重新验证提示。

### 3.7 Recommended Actions
- 行动按「需先确认 / 可并行 / 后续」分组；卡片显示问题、下一步、处理对象、关联证据或资料缺口。点「编辑」→ 显示修改与依据 → 保存为待确认。点「确认」→ 显示确认记录 → 可选入回复。点「不采用」→ 保留记录和恢复入口；「已确认」不代表行动已执行。
- 待确认项支持标为「向客户询问 / 内部核实 / 暂缓」；填写问题或处理人后明确其去向。只有面向客户的内容经用户选用才进入商务回复；内部风险判断和内部笔记默认不进入外发文案。

### 3.8 Communication Studio
- 选择已确认的业务要点、需问客户的问题、语气和语言（默认英文）→ 生成期间保留现有文本 → 展示可编辑预览；数量、交期、型号、认证和报价不得将未知内容写成承诺。缺口优先写成问题；用户也可跳过生成直接编辑。
- 生成其他语言或重新生成 → 展示独立候选与差异 → 用户选择应用到目标语言草稿；不覆盖手工编辑或其他语言版本。编辑显示「未保存」；检查重要承诺和未替换占位，不把待核实信息变成系统已确认结论。
- 点「保存版本」→ 显示保存中 → 成功后展示版本号、语言、作者与时间，并更新列表。空白不保存；有未替换占位时提示并引导修正，仍可保存工作版本并标记「含待补内容」。保存失败仍保留可编辑正文；重试成功只新增一个版本。
- 打开历史 → 预览只读正文及差异 → 「恢复到编辑区」带回所选语言内容。已有未保存内容时先提供保存、放弃或取消；恢复后是未保存编辑，再保存生成新版本，不删除或重写原历史。

## 4. 核心流程与分支

1. **标准路径：** 新建 → 粘贴邮件并添加 PDF → 预览并创建 → 核对数量、目标市场与特殊规格 → 对比候选 → 确认主推与备选 → 核实客户与证据（可选）→ 确认并选用行动 → 生成英文 → 手改 → 保存版本 → 历史可查看。
2. **信息不足：** 图片识别只获得规格 → 数量、市场保留待确认 → 保留初步候选，不承诺 MOQ/认证 → 选中澄清事项 → 生成询问型回复 → 保存。
3. **来源故障：** 知乎超时 → 局部显示失败 → 海外资料、人工作业和既有证据仍可访问 → 仅基于可用事实确认行动 → 保存回复。
4. **后续修订：** 客户变更数量 → 已确认的相关 MOQ/交期与行动待复核 → 对比后再确认 → 原回复不变，编辑区提示更新依据 → 保存新版本；如需还原，历史预览后恢复到编辑区再保存。

## 5. 交互状态定义

- **正常：** 呈现有效内容、来源和当前主操作；不默认打开 L3 或自动覆盖输入。
- **加载 / 提交中：** 初载用结构占位；分析、来源搜索和生成仅局部反馈任务名。保留可读内容和已编辑文本，保存期间防重复点击；完成后更新原区域，不抢焦点。
- **空：** 无询盘引导新建；筛选无结果引导清除条件；无证据引导搜索/补充；无历史提示首次保存后出现。空不等于失败。
- **错误：** 就地说明失败对象、原因和下一步。重试保持原输入；保存失败不得显示成功或前进状态。列表加载失败不遮蔽已打开内容。
- **数据不足：** 有部分结果但关键字段未知，明确缺项、影响与补全入口；保留澄清路径，未知项不计为满足。
- **外部信息源不可用：** 来源旁显示不可用及重试入口（若适用）；其他来源继续，旧证据注明获取时间。与无结果区分；不弹出阻断整页的对话框。
- **用户修改：** 原值/新值可查，显示未保存或人工修改待确认；可取消、保存、确认。离开前守护未保存内容。
- **保存成功：** 区域内持续显示保存状态与时间；回复显示版本号和「查看历史」。成功通知不抢焦点、不替代持续状态。

**优先规则：** 未保存输入不可被任何刷新、错误或部分成功覆盖；来源故障与数据不足可并存，不能用一个全局状态隐藏其他区域。发送不在本阶段设计中。

## 6. 组件清单

- **导航：** 可搜索列表、状态筛选、选中行、粘性询盘页头、区域导航。
- **导入与编辑：** 多格式导入面板、附件状态行、原文预览、字段级编辑、差异预览、离开确认。
- **决策：** 业务摘要条、缺口卡、候选对比矩阵/窄屏卡、确认控件、行动卡与证据选择器。
- **可信与详情：** 类型标签、独立可信标签、来源链接、证据抽屉、原文定位、冲突对照。
- **回复与反馈：** 语言选择器、正文编辑器、生成候选预览、版本历史、局部占位、空状态、行内错误和保存状态条。

**视觉与可访问性：** 中性浅色工作面、克制分隔线、唯一主操作强调色；数字与单位并排，状态不只靠颜色。列表、比较与编辑皆可键盘操作；抽屉打开聚焦标题或首控件，关闭后焦点返回触发点，模态详情 Esc 可关闭（有编辑先提示）。读屏可读状态和错误关联，移动主要触控目标 ≥44px，不用悬停作为唯一入口。

## 7. 验收标准（产品评审 / 后续测试）

- **AC01 导入：** 分别使用有效文本、PDF、图片、EML，可预览、修订、创建并回到原文；损坏文件与有效文件混合时只会按明确选择导入成功项。
- **AC02 导航：** 搜索和状态筛选可叠加；切换再返回保留上下文；未保存状态下选择继续编辑不会丢内容。
- **AC03 三级展示：** 首屏包含需求、匹配、缺口与下一步，不出现长证据列表；从 L1 可达对应 L2，再直达 L3 原文；关闭返回触发点。
- **AC04 信息性质：** 给定只有邮件声明和无来源推断的询盘，标记能区分陈述、推断、待确认；人工确认推断后仍不显示为事实。
- **AC05 多对多：** 两个需求分别绑定多个 SKU，其中一个 SKU 跨需求复用；五项维度均可核查，调整一个匹配关系不改其他关系。数量变了，相关 MOQ 确认待复核、无关确认保持。
- **AC06 客户调查：** 出现同名企业时未选择主体前不自动归因；无结果不显示低风险；人工覆盖保留依据与历史。
- **AC07 证据链：** 从任一已关联行动追溯问题和原始证据；两条相反证据可并读并留处置理由；无证据的建议仅指向核实或补资料。
- **AC08 降级：** 分别模拟知乎关闭、超时及全部外部来源不可用；仍可用邮件和企业资料完成匹配/澄清、确认行动并保存回复。
- **AC09 回复：** 英文与另一语言可独立生成、编辑和保存；重生成不覆盖人工正文；保存失败可重试；恢复旧版再保存产生新版本且历史完整。
- **AC10 状态覆盖：** 逐项触发第 5 节八种状态；任何失败不显示成功，不清除输入；局部分析中其余区域仍可用。
- **AC11 响应式与键盘：** 在 1440px、1024px、390px 完成标准流程与历史恢复；无页面横向溢出或被遮挡的主操作；键盘可完成选择、确认、保存和抽屉往返。
- **AC12 闭环边界：** 保存成功可在列表及历史观察到；全程不自动发送，未核实承诺不由系统写成确定措辞。
